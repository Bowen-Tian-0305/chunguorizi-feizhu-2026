## 单实例容器方案

适合已有阿里云 ECS / 轻量应用服务器的 Linux 实例。前置条件：Docker Compose、可解析到服务器的域名、公网 80/443 可访问。中国内地实例的域名还需满足备案要求；是否改用其他托管入口，需要实际核查后决定。

1. 复制 `.env.example` 为 `.env`，只在服务器填写服务密钥。加上 `DOMAIN=你的子域名`，不要写协议和路径。
2. `docker compose config --quiet` 检查配置。不要公开 `docker compose config` 的完整输出，它会展开环境变量。
3. `docker compose up -d --build` 启动。只公开 Caddy 的 80/443，应用 4173 不映射到宿主机。
4. 用另一台设备打开 `https://你的子域名/`，验证城市选择、固定示例、实时酒店查询、麦克风授权/转写、截图提取、附近餐饮/步行路线、保存方案。检查 `/api/health` 不能代替实际功能验证。
5. 经过用户最终验收，再把实际地址更新到 README 与官方投稿 Issue。

`Caddyfile` 配置 HTTPS 与反向代理，覆盖转发 IP 为直连访问者地址。此配置假定 Caddy 直接面向访客；若再加 CDN，需重新核验代理 IP 信任链。应用仅通过内部容器网络访问。

## 额度保护

- 全站每天默认 30 次模型端点请求，每 IP 每小时及每天各 5 次。语音转写后再解析需求是两次请求；次数不等于旅行方案数。
- `MODEL_QUOTA_FILE=/app/state/model-quota.json` 使用命名持久卷，容器重启/重建继续计数。每次请求先原子写入账本再调用模型；文件损坏或不能写入则关闭实时调用。
- 北京时间零点重置。账本只保存每日随机盐和 IP 的 HMAC 摘要、计数；不保存原始 IP、录音、图片、需求文本。不要发布账本。
- `REALTIME_AI_ENABLED=0` 可以关闭实时 AI，固定示例与手动填写仍可用。不要删除 `app-state` 卷；`docker compose down -v` 会删除计数和证书存储。
- 该方案只支持一个应用实例；不能直接扩容成多个账本独立的服务。临时云函数文件系统不算持久卷，改用 FC 时需独立共享存储和部署验证。
- 调用次数限制不是费用上限。上线前还要核查实际使用的模型免费额度、开启适用模型的免费额度耗尽停止，并核查云计算及地图/酒店服务的配额。模型账户保护尚未代用户更改。
