# 从订房价格到每一个早晨

## 面向的真实选择

同行两个人，住两晚，含早多240元，但退房日要赶车。按住宿晚数平均会得到60元/人/次；如果实际上只吃一次，则变成120元/人/次。这个差异决定了该选哪档房价，以及哪一天留给当地早餐。

用户可以选具体早餐日期。比较器显示两种成人早餐增量预算，并同步逐餐计划：

- 不含早、全部外出：外出人均预算 × 成人数 × 早餐晨数。
- 含早、其余早晨外出：全程套餐价差 + 外出人均预算 × 成人数 × 未用酒店早餐晨数。
- 持平的人均价格：全程套餐价差 ÷ 成人数 ÷ 实际使用次数。

示例为两位成人、两晚、套餐价差240元、外出预算35元/人。只用一次含早时，两种增量预算分别为140元和310元；省心、当地味和赶车时间仍由用户权衡。示例金额不代表实时酒店商品报价。

## 对三个评分方向的贡献

| 方向 | 实际设计与可验证结果 |
| --- | --- |
| 创新性 | 把酒店权益与真实使用日历连接，让用户即时试不同吃法；AI理解语音和截图中的条件，确定性代码计算金额 |
| 完整度 | 日期选择、餐馆选择、计价、逐餐安排和导出互相一致；0次使用、份数不足、费用持平、儿童未知有独立处理 |
| 市场价值 | 面向亲子、赶早出门与当地美食偏好；分享卡便于同行人商量，复制问店话术帮助补齐预订条件 |

这不是评委打分或获奖预测。仍需提高的方面是酒店早餐实际菜单与当日营业资料的覆盖，以及对用户实际使用效果的长期验证。

## 已完成验证

- 金额边界与跨月早餐日期：`npm test`。
- 浏览器实际交互：两晚只吃一次、0次使用、两种费用持平、早餐天数越界、亲子费用未知、早于早餐开放参考时段出门。
- 将外出门店选入早餐行，会自动减少酒店早餐使用次数并重新计价。
- 390px手机视口没有横向溢出；分享卡可以打开、关闭并保存图片。
- 公网健康、周边地点与步行路线可用；模型接口沿用此前实际验证的实现。

## 信息边界

两档房型、日期、取消规则和其他权益不一致时不能把全部价差归因于早餐。儿童收费未核实，不给全家报价。门店存在或路线可达不代表该餐次营业、供应特定菜品或满足过敏安全；必须再次核对。早餐日期是用户计划，不是酒店已确认的预订权益。
